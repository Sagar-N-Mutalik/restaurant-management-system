Examiner Viva Defense Flashcards

High-yield oral viva defense answers expected by professors, lecturers, and external examiners.

Q1 What is the fundamental difference between Unit Testing and Integration Testing in your system?
Examiner Model Answer: "Unit testing isolates individual modules (e.g., NormalPricing, HappyHourPricing, or ExtraCheeseDecorator) in pure Python without touching databases or network layers, validating algorithmic correctness in microseconds. Integration testing, by contrast, exercises multiple interconnected subsystems together—specifically validating that our OrderProcessingFacade coordinates Django ORM database persistence, table occupancy locking, and Observer push alerts to the kitchen simultaneously."
Q2 Why are tests executed against an isolated in-memory database rather than live restaurant data?
Examiner Model Answer: "Running automated tests against live production databases risks corrupting customer bills, altering table occupancy states, or skewing audit balances. Django dynamically spins up an isolated in-memory SQLite sandbox for the test run and safely tears it down afterward, guaranteeing 100% idempotent test runs and zero data contamination."
Q3 What are Boundary Value Analysis (BVA) and Equivalence Partitioning in Black-Box Testing?
Examiner Model Answer: "Equivalence Partitioning divides the software's input data domain into valid and invalid partitions (e.g. valid table IDs 1–10 vs non-existent table IDs like 99999). Boundary Value Analysis specifically tests extreme edge conditions on partition borders (e.g. 0.0 price, negative price values, empty cart arrays, and maximum seat capacity). Our tests assert that invalid partitions and boundary breaches are safely handled with HTTP 400/405 error responses without 500 server crashes."
Q4 Why did you implement Black-Box testing for the REST API endpoints?
Examiner Model Answer: "External consumer devices (like guest mobile phones and QR scanners) do not possess internal knowledge of Django views or models. Black-box testing validates that from an external HTTP perspective, the API strictly adheres to REST protocols: responding HTTP 201 Created on valid order payloads, HTTP 405 Method Not Allowed on illegal GET calls, and HTTP 400 Bad Request on invalid table numbers."
Q5 What is the role of Smoke Testing in your CI/CD delivery pipeline?
Examiner Model Answer: "Smoke testing (Build Acceptance Testing) provides an ultra-fast sanity check executed immediately after deployment or code changes. In under 0.15s, it confirms that all 7 primary application views (Customer Landing, Menu, Kitchen KDS, Bill Payment, Reports Hub, and Testing Guide) respond HTTP 200 OK without unhandled template or syntax exceptions."
